从分类到生成：大模型时代的 NLP

NLP 的下半场：从'给文本贴标签'到'让模型写文本'，生成式范式如何重构一切任务。

#NLP #文本生成
目录

NLP 章节前 7 篇讲的都是”判别式”思路：给文本分类、抽取、匹配——读懂文本。但大模型时代的主旋律是”生成式”：让模型写出文本。这一篇做 NLP 版的”收尾 + 前瞻”：理解生成式范式如何重构了 NLP 的任务地图，以及它和你正在做的大模型应用的关系。

一次范式位移：从判别到生成

传统 NLP：每个任务一个专用模型 + 专用结构（分类头、序列标注头……）。

生成式 NLP：**一个模型，所有任务都变成”写一段话”**。

传统任务 生成式改造
文本分类 让模型写”这属于：质量缺陷-蜂窝麻面”
抽取关键信息 让模型写”部门：质量部；金额：52万”（结构化输出）
语义相似/检索 让模型写”回答/拒绝”或输出检索 query
问答 让模型直接写答案（并给出处）

关键转变：过去为每个任务设计”任务头 + 损失函数”，现在只用一个”预测下一个词”的目标——任务差异全部通过指令（Prompt）表达。这就是你看到的”一个模型啥都能干”的原因。

生成模型的三个机制

从 Transformer 章节的迷你 GPT 到真实 LLM，生成靠三个机制：

  1. 自回归：逐 token 预测下一个，把新 token 拼回去再继续；
  2. 上下文窗口：能看到的前文长度（现代 LLM 从几千到百万 token）；
  3. 解码策略：训练时学”概率分布”，生成时按策略挑 token：

temperature 是生成质量最重要的旋钮：事实性任务（RAG 回答）用低温度（0.1~0.3）求稳，创意任务（头脑风暴）用高温度（0.8+）。

生成时代 NLP 的新任务形态

生成式重构了 NLP 的任务版图，新增了几类”生成特有”的核心能力：

  • 指令遵循：听懂任务要求（”只依据给定资料回答””输出 JSON”）；
  • 结构化输出：把回答约束成 JSON/schema，让程序能直接消费（接业务系统）；
  • 长上下文利用：在几十万 token 的上下文里精准取用信息（RAG 与长文本处理）；
  • 工具调用（Function Calling）：模型不只写文字，还能”决定调用哪个工具、传什么参数”——这是 Agent 的技术底座。

这些正是大模型应用版块（RAG、Agent、MCP、Function Calling）的核心命题——**NLP 的下半场不再只属于 NLP 工程师，而是属于”大模型应用工程师”**：你正在做的建知云、建智协，就是这个时代的 NLP 落地形态。

判别 vs 生成的取舍

生成模型不是万能解，工程上要清醒：

场景 判别式（分类等） 生成式（LLM）
成本 便宜、快、可控 贵、慢、有幻觉风险
数据需求 需要标注数据 免训练（提示词即可）
长尾覆盖 差（样本少就学不好） 好（通用知识兜底）
可控性 输出结构严格 需约束（schema/低温度）

工程最优解常常是混合的：高频、结构明确的走判别模型（快、省、稳），长尾、模糊的走 LLM 兜底（就像层级分类篇的”置信度闸门 + LLM 二审”）。让每种模型做它擅长的事——这是大模型应用时代最重要的工程判断力。

小结

NLP 走完了从”读”到”写”的范式位移：判别式模型贴标签、生成式模型写文本，任务差异被 Prompt 吸收。理解自回归生成、解码策略、判别/生成的取舍，你就握住了从传统 NLP 通往大模型应用（RAG、Agent）的钥匙。NLP 八篇收官——下一个版块，我们把”预训练 + 微调”这套范式，正式用到模型本身：Fine-tuning。
