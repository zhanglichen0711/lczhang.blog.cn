对齐：RLHF 与 DPO

SFT 让模型会用，对齐让模型'答得好'：RLHF 的奖励模型与强化学习、DPO 的免强化改造。

#微调 #RLHF #DPO
目录

SFT 之后模型能”按指令办事”了，但它还可能：长篇大论、编造出处、回答不安全内容。对齐（Alignment）是让模型的回答”符合人类偏好”的最后一步——最有名的是 RLHF（基于人类反馈的强化学习），而 DPO 用更简单的方式实现了同样的目标。这一篇把两者的原理与取舍讲清楚。

对齐要解决什么

SFT 学的是”格式正确”，对齐学的是”质量与价值观”：同一道题可能有多种合规回答，有的简洁有的啰嗦、有的谨慎有的胡诌——怎么让模型偏向人类更喜欢的那个。数据形态从”标准答案”变成”回答的好坏排序”。

RLHF：三步走

第一步：收集人类偏好数据

第二步：训练奖励模型（Reward Model）

用偏好数据训练一个小模型：给它”提示 + 回答”，输出一个分数——学的是”人类觉得这回答好不好”：

第三步：用强化学习优化策略

把 SFT 好的模型当”策略”，让它生成回答 → 奖励模型打分 → 用 PPO（强化学习算法）更新，让模型”往高分方向走”：

RLHF 的问题：PPO 训练不稳定、要同时维护 4 个模型（策略/参考/奖励/价值）、工程复杂。于是有了更简单的替代。

DPO：跳过强化学习

DPO（Direct Preference Optimization，2023）发现了一个巧妙的数学等价：RLHF 的最优策略可以直接从偏好数据里推出来，不需要训练奖励模型、不需要 PPO。训练目标变成一个简单的”偏好损失”：

DPO 的工程价值：不用奖励模型、不用强化学习，一次普通的前向/反向就能完成对齐——复现简单、稳定，已成为社区对齐微调的主流选择（很多开源模型的”对齐版”就是用 DPO 做的）。

RLHF vs DPO 怎么选

维度 RLHF DPO
组件 奖励模型 + PPO 只需要偏好数据
训练复杂度 高（不稳定） 低（像普通微调）
数据需求 偏好数据 偏好数据
上限潜力 理论上限更高 略受局限
团队现实 大厂/资源足 多数团队首选

务实建议：没有专门 RL 工程团队，直接 DPO；效果好，成本一个数量级地低。OpenAI 那种”GPT-4 级”的对齐用 RLHF 打磨出的边际优势，对绝大多数领域应用不值那个工程代价。

对齐的完整流水线（一张图记完）

对应你简历里”LoRA / QLoRA 高效微调 + RLHF 与 DPO 对齐”的占位规划——这条流水线就是”从通用模型到可用的领域模型”的标准工序。

对齐阶段的注意事项

  1. 学习率更小（1e-6~1e-7）、epoch 更少——对齐只是”微调方向”，不是”重新学习”；
  2. 偏好数据质量是全部——chosen/rejected 对差异要真实明显，模糊的对比教不出方向；
  3. 别过度对齐——压得太狠模型会变”敷衍”（安全但无用），要留平衡；
  4. 别忘了评测——对齐前后都要跑领域评测集（最后一篇细讲）。

小结

对齐让模型从”会用”到”答得好”：RLHF 用奖励模型 + PPO 显式优化人类偏好（强但复杂），DPO 用偏好数据一步到位（简单稳定，团队首选）。完整流水线是”预训练 → SFT → DPO/RLHF”。对齐是微调的”最后一公里”，而它的效果同样取决于数据——偏好数据里的每一次”这个更好”都在给模型校准价值观。

模型改到满意了，最后一篇是微调工程师的”质检关”：怎么系统化地评估微调效果，避免”感觉变好了”的错觉。
