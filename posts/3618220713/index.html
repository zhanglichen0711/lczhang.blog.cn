Agent 简介：从对话到自主行动

Agent 是能感知、决策、行动的实体。它和大模型问答的区别在于：模型负责想，Agent 负责把想法变成行动闭环。

#Agent
目录

从 RAG 到 Agent，是大模型应用从”回答问题”到”完成任务”的跃迁。RAG 让模型能回答它没学过的问题（外挂知识）；Agent 让模型能动手做事——查数据、调接口、操作工具，把一个多步骤的任务从头做到尾。这是 AI 应用当前最热、也最容易被误解的方向。这篇先把 Agent 到底是什么讲清楚，再划清它和大模型问答的边界。

三个容易混在一起的概念

“Agent”是这行被滥用最严重的词之一。把三个不同层次的概念分开，很多讨论才不会鸡同鸭讲：

1. 模型（Model）：只会”生成文字”的引擎。你问它”上海明天天气如何”，它只能告诉你”我建议你查天气应用”——它知道该查，但它没有手。

2. 对话系统（Chat）：模型 + 对话界面。能做问答、能聊天，但同样不能做事——它没有”行动”的出口。

3. Agent（智能体）：模型 + 工具 + 循环。它能感知（接收任务、观察环境反馈）、决策（决定下一步做什么）、行动（调用工具、执行动作），然后根据行动结果决定下一步——形成一个”感知-决策-行动”的闭环。

用一句话区分：模型会”说”，Agent 会”做”。 一个能回答”如何查天气”的是对话系统；一个能帮你查好天气、再决定要不要带伞、并把提醒发到手机上的，才是 Agent。

Agentic 程度：不是越自主越好

“Agent”和”Agentic”是另一个常被混淆的概念：

  • Agent 是实体——一个能感知、决策、行动的组件；
  • Agentic 描述的是自主程度——这个系统有多”放手”。

自主程度是一条光谱，不是开关：

工程上最常见的错误是盲目追求高自主——总觉得”让模型自己规划”才高级。实际上：

  • 能写死成 workflow 的步骤，写死更便宜、更稳、更容易测；
  • 高自主只在”任务无法预写流程”时才值得用（如开放式的”帮我研究一个课题”）；
  • 自主度越高，失控风险越大、评测越难、成本越不可控。

判断标准：用最低的自主度完成任务。能 workflow 就不 Agent，能单轮就不多轮。自主是能力，不是目的。

Agent 能做什么、不能做什么

Agent 擅长： 多步骤、需要工具、结果可验证的任务——查资料并汇总、跨系统操作（查库存→下单→通知）、需要根据中间结果调整的任务。

Agent 的边界（必须清醒）：

  • 它不会凭空变出模型没有的能力——模型的推理上限就是 Agent 的上限；
  • 它会把错误放大——一个错误决策可能触发一连串错误行动，比单次问答危害大得多；
  • 它需要”可终止性”设计——没有步数上限、没有确认机制、没有回滚，Agent 就是一颗定时炸弹。

小结

Agent 是能感知、决策、行动的实体，核心是一个”决策-行动-观察”的循环，而不是更聪明的模型。把它和对话系统分开：模型会说，Agent 会做。工程上的起点是理解自主度光谱——能用低自主完成的，别上高自主。最小 Agent 骨架里已经藏着步数上限、工具白名单、观察回填这些贯穿整个系列的关键设计。
