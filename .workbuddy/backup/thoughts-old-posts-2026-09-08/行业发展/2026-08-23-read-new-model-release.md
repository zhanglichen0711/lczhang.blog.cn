每次新模型发布，信息密度很低、对比图很多。做应用可以用一张很短的清单过滤噪音。

## 五个问题

1. **上下文是否真能用满？** 标了 128k 不代表 80k 时引用还稳。规范问答往往在「检索很多、生成很长」时先崩。
2. **工具调用是不是一等公民？** JSON / Function Call 的失败率比综合榜更影响项目。
3. **价格和限速？** 同一条 RAG 贵 4 倍，通常意味着必须上缓存和小模型分流。
4. **开放程度？** 接口是否兼容、能否本地部署、数据能不能留在自己这边。
5. **自己的评测集？** 用业务里的题目跑一遍，比任何官方榜都重要。

## 写进笔记的方式

不要复制新闻稿。留下：适用场景、不适合场景、准备替换谁、迁移成本。三个月后再看，会发现哪些判断经得起时间。
