### 环境层面的大坑（重要，下次注意）
- **safe-delete shim**：本环境的 bash `rm`/Python `os.remove`/`shutil.rmtree`/PowerShell `Remove-Item` 全部被 genie-safe-delete 包装，走回收站（trash）。回收站组件损坏（"系统不支持该功能"）→ 删除全部失败。
- safe-delete 有**批量阈值**：一个 turn 内累计删除操作 >50 次后，后续所有删除被整体拒绝（SAFE_DELETE_BULK_CONFIRM_REQUIRED），且计数会跨命令累计。→ 大文件清理要一步到位，别反复小步删。
- **public 目录文件被 WorkBuddy 预览面板锁定**：`present_files` 打开 localhost:4000 预览后，WorkBuddy.exe 进程持续持有 public 里 HTML 文件句柄，导致 hexo generate 写 public 时 EPERM（每次报错文件都不同）。杀 node 进程没用，锁的是 WorkBuddy 预览面板。
- 结论：本地重新 build 常被预览面板/文件锁卡住，但**不影响成果**——source 目录才是内容源，用户 `npm run build`/`npm run deploy` 时在干净环境重建即可。本地预览可用 `hexo server`（动态渲染，不写 public）。
- db.json 被删后若报 `utcOffset` 错误，是 db.json 半写入损坏的连锁反应，重建 db.json 即可，不是文章 data 字段问题。
