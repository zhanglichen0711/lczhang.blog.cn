被问过很多次"有什么学习资源推荐"，一直没写是因为怕写成一份"全网最热清单"——那种清单除了收藏夹吃灰，没什么用。这篇只写**我实际在用、且真的解决过问题**的工具，按一条 AI 应用的链路来排，而不是按热度排。

## 模型调用

- **OpenAI 兼容接口作为标准**：不管背后是 DeepSeek、Qwen 还是自部署的 vLLM，统一用 OpenAI 兼容协议接——换模型只改 base_url 和 key，代码不动。这是我认为 2025 年以来最重要的一个工程习惯。
- **大厂 API + 开源自托管混用**：公开数据走 API 图省事，敏感数据走本地小模型。具体怎么选，见行业观察里那篇《开源模型与 API》。

## 检索与存储

- **MySQL**：业务元数据、问答记录、权限表——关系型数据它最稳；
- **Milvus**：向量检索，配合权限下推（把权限写进查询条件），是 RAG 的主力；
- **Redis**：缓存 + 语义缓存，把重复的模型调用挡住——它是成本治理的第一道闸。

## 评测与回归

- **自己的 30 道题**：固定评测集，覆盖切分边界、权限、长文档引用这些真实场景（具体方法见《学一个新东西的最小闭环》）；
- **坏案例归档**：每次线上答错的案例进回归集，换模型、改 prompt 后重跑，用通过率说话；
- **Langfuse**：LLM 调用链追踪——它能回答"这次坏回答是哪一环出的问题"，是归因能力的工具化。

## 可观测与成本

- **结构化日志 + request_id**：日志能按一次请求串起来，排查问题的第一现场；
- **Prometheus + Grafana**：错误率、延迟、token 消耗的看板与告警；
- **语义缓存 + 路由分层**：简单请求走小模型、疑难才上大模型——成本不是省出来的，是分出来的。

## 部署与工程

- **Docker + Compose**：本地和单机部署的主力，镜像固定版本、健康检查、非 root 运行；
- **GitHub Actions**：博客和项目的 CI/CD，push 即构建发布；
- **vLLM**：自托管推理引擎，OpenAI 兼容，显存和吞吐的调参都写在笔记里了。

## 一个原则

工具清单会过时，但选择工具的原则不会：**每环只留一个顺手的，标准接口优先，能自托管的敏感数据不送出去。** 工具是链路上的零件，别让选型本身消耗太多精力——**真正拉开差距的从来不是工具多全，而是链路多稳。** 这份清单半年后大概率会变，变的那些我会更新，不变的是选择它们的逻辑。
