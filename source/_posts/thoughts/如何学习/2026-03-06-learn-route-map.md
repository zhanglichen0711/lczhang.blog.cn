经常有人问我学习路线，其实答案一直摆在这：**这个博客的 notes 版块本身就是我的路线图。** 从最早的基础语言笔记一路写到今天的推理部署，它不是按学科目录排的，是按"做一个 AI 应用需要打通哪些环节"排的——今天把它整理出来，既是复盘，也给想走这条路的人一个参考。

## 路线图总览：一条链路，五个台阶

```
编程基础（Python / Linux / 数据三件套）
   ↓ 有了写代码和数据的能力
后端服务（FastAPI / Node，把逻辑包成接口）
   ↓ 有了交付服务的能力
数据与存储（MySQL / Redis / Milvus）
   ↓ 有了管数据、做缓存、做检索的能力
模型训练与微调（ML / DL / PyTorch / Transformer / NLP / Fine-tuning）
   ↓ 懂了模型内部发生了什么
模型部署与推理 + 工程化（vLLM / 量化 / Docker / K8s / CI / 可观测 / 安全）
   ↓ 能把系统稳定跑在生产上、出了问题查得到
大模型应用（RAG / Agent / 多模态）← 前五阶的汇合点
```

## 几个关键决策点

回头看，这条路上有几个当时没觉得、现在看很关键的决策：

**先学"怎么把代码写成服务"，再学模型。** 很多人路线反了：先啃 Transformer，结果要部署时连 FastAPI 都不会。我庆幸顺序是先后端再模型——因为 AI 应用的本质是"带模型的 Web 服务"，服务能力是地基。

**检索（Milvus）和大模型应用（RAG）之间，隔着一整层工程。** 光会调向量库不算会做 RAG，中间的切分、权限、评测才是拉开差距的地方——这也是我在笔记里把「数据与存储」单独铺开的原因。

**部署和微调同等重要。** 能训练一个 LoRA 不算完，能把它用 vLLM 跑起来、压进 Docker、监控它的成本和延迟、出了问题能定位——这套工程闭环才是简历上"能落地"的证明。

## 每个版块对应一种能力

这套路线图最有价值的地方在于**可验证**：每一阶都有对应的交付物。学完 Python 能写脚本，学完 FastAPI 能起服务，学完 Milvus 能跑检索——**不是"学过"，是"能交付"**。这也是我坚持把学习笔记写成教程而非摘抄的原因：笔记要能证明你走到了哪一步。

## 给想照抄的人

- 不要跳阶：跳过"数据与存储"直接学 RAG，会在权限和一致性上栽跟头；
- 每阶都要有产出：笔记、项目、或者至少一个跑通的 demo——**没有交付物的学习不算完成**；
- 五阶走完，你自然知道该往哪个方向深挖——因为你会开始遇到真实的问题，而真实的问题会告诉你下一步学什么。

路线图不是让你按图索骥地走两年，而是让你**在迷路的时候知道自己在整条链路的哪个位置**——知道位置，就永远知道下一步。
