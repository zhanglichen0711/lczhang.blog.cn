评测系列的框架（评测集、Judge、线上评测）在多模态场景依然适用，但多模态评测有一个文本评测没有的难题：**判断"看对没有"比判断"说对没有"难得多。** 文本回答可以比对标准答案；模型说"这张图里有裂缝"——你怎么验证图里到底有没有裂缝？**图的"真相"没有现成的文本可比对，这是多模态评测的核心难点，也让多模态幻觉（看图说瞎话）成为最难抓的问题。**

## 为什么多模态评测更难

**难点一：图的"正确答案"难以表达。** 文本评测可以写"期望输出包含 A、B、C"，图怎么表达期望？"图里应有裂缝，位于左上角"——这种期望本身就要人来标注，无法规模化。

**难点二：模型的错误更难发现。** 文本模型编一个不存在的引用，你能看出来；VLM 说"图里有渗水痕迹"，如果图里确实没有，人眼不细看很难发现——**模型描述得越自信，错误的隐蔽性越强**。测试发现，VLM 在模糊图上"看图编细节"的比例不低，而这类错误在纯文本流程里几乎不会被触发。

**难点三：评测本身要"看图"。** 判断 VLM 输出对不对，评测者（无论是人还是 Judge 模型）也得看图——于是评测又多了一层"看错"的风险。**用 VLM 评 VLM，误差叠加。**

## 多模态评测的三个维度

虽然难，但评测仍要分层做。多模态模型的应用评测分三个维度：

**维度一：感知准确性（看对没有）。** 模型是否准确描述了图的客观内容——图里有什么、没有编造什么。这是多模态评测的"地基"，也是最难自动化的部分。

**维度二：理解与推理（看懂没有）。** 不仅看到，还能正确推理——"这张缺陷图说明施工时什么环节出了问题"。这部分和文本推理评测类似，可以用 Judge。

**维度三：业务正确性（做对没有）。** 落到业务：质检判断对不对、文档抽取的信息准不准。这部分**可以用业务结果验证**——抽取的信息和人工标注比对，是最可靠的。

**评测策略的启示：能落到"业务结果"的维度（三），是最容易测也最有价值的**——文档解析抽出来的字段对不对，直接和人工标注比对就行，不需要"评价看图能力"这种虚的维度。

## 感知准确性怎么测：多信号交叉

感知准确性（图里到底有没有 X）最难自动化，实用做法是**多信号交叉**：

**信号一：用传统 CV 做"客观锚点"。** 缺陷检测类的感知，先用传统 CV（检测器）给图打一个"客观标签"（有无缺陷、缺陷框）。VLM 的描述和 CV 结果比对——**一致则可信，不一致则标记争议**。CV 是"笨但确定"，正好给"聪明但会编"的 VLM 当锚：

```python
def cross_check_vlm_with_cv(image, vlm_output):
    """VLM 描述 与 CV 检测结果交叉验证"""
    cv_findings = cv_detect(image)               # 客观锚点：检测器结果
    vlm_mentions = extract_defects(vlm_output)   # VLM 说了哪些缺陷

    agreed = set(cv_findings) & set(vlm_mentions)
    vlm_only = set(vlm_mentions) - set(cv_findings)   # VLM 说有、CV 没有
    cv_only = set(cv_findings) - set(vlm_mentions)    # CV 有、VLM 漏了

    return {
        "agreed": agreed,
        "vlm_only": vlm_only,      # 疑似幻觉（VLM 看图编的）
        "cv_only": cv_only,        # VLM 漏检
        "vlm_hallucination_risk": len(vlm_only) > 0,
    }
```

**信号二：区域提问（针对性验证）。** 与其问"图里有什么"（容易泛泛而谈、容易编），不如针对具体区域问"这张图的左上角区域有没有裂缝"——**问题越具体，越难编**，也越容易和 CV 的框比对。

**信号三：人工抽检（终极裁判）。** 争议样本（VLM 与 CV 冲突、低置信）必须人工看——**人工复核的优先级留给"机器判断不一致"的样本**，而不是全量人工。

## 业务场景评测集：以"任务"为单位

多模态评测集也应以任务为单位组织（呼应 Agent 评测篇），每个任务带"可验证的业务期望"：

```python
MULTIMODAL_EVAL = {
    "document_parse": {          # 文档解析任务
        "cases": [
            {"image": "contract_p1.png",
             "expect": {"fields": {        # 抽取字段与人工标注比对
                 "合同编号": "HT-2025-001",
                 "甲方": "XX 建设公司",
                 "金额": "1,280,000 元"},
             "verifier": "field_match"}},   # 字段精确比对（可规则化）
        ],
    },
    "defect_judge": {            # 缺陷判断任务
        "cases": [
            {"image": "defect_03.jpg",
             "expect": {"defect_type": "裂缝",
                        "severity": "中等"},
             "verifier": "cv_cross_check"},  # 与 CV 结果交叉
        ],
    },
}
```

**注意：评测期望尽量用"可规则化的业务结果"（抽取字段对不对、缺陷类型与 CV 是否一致），而不是"让评测模型打分看图能力"。** 可验证的期望越多，评测越可靠。

## Judge 在多模态里的用法与坑

LLM-as-Judge 在多模态场景依然有用，但要注意：

**用法：让"更强的多模态模型"做相关性/完整度判断**——回答是否贴题、是否覆盖了该说的点。这类"语言层"的判断，Judge 可靠。

**坑一：Judge 也要看图 → 误差叠加。** 让 VLM 评 VLM 的感知准确性，等于让"可能看错的"评"可能看错的"。**感知类问题（图里有没有 X）别用 Judge，用 CV 锚点 + 人工；语言类问题（答得贴不贴题）才用 Judge。**

**坑二：Judge 模型本身的多模态幻觉。** Judge 也可能"看图编"——它说"回答准确描述了图"，可能图里根本没那东西。**Judge 的结论要抽查复核，别全信。**

## 线上多模态评测

线上评测的框架（trace、规则门禁、抽样、差评回流）在多模态场景直接复用，加两条：

- **记录输入图的质量**：分辨率、模糊度、大小——排查"最近判断变差"时，先看是不是输入图质量下降（拍照设备变了、上传压缩过了）；
- **给每次判断打置信度**：低置信输出标记"待复核"，抽样复核率与置信度挂钩——**让系统自己知道"哪些判断不可靠"。**

## 小结

多模态评测的核心难点：图的"真相"没有文本可比对，导致看图说瞎话难以发现。解法是分维度：感知准确性（看对没有）用 CV 当客观锚点交叉验证 + 区域提问 + 人工抽检争议样本；理解推理用 Judge（但只评语言层，别让 Judge 评感知）；业务正确性用可规则化的结果比对（最可靠）。评测集以任务为单位、期望尽量可验证。**多模态评测的哲学：别试图"直接判断模型看没看对"，而是用多个独立信号交叉——当它们不一致时，问题就暴露了。这是对付"隐蔽幻觉"唯一可靠的办法。**
