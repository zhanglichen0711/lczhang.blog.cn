做 AI 应用和传统开发最大的不同：**代码改坏了会报错，prompt 或模型改坏了不会报错——它只是悄悄变差。** 一个 RAG 系统，你换了 embedding、改了切分参数，代码照样跑，但回答质量可能已经下降了。没有评测，你根本不知道。**评测就是把"感觉好/坏"变成"可比较的数字"的手段——它是 AI 应用工程的度量衡，没有它，一切优化都是玄学。**

## 为什么 LLM 评测比传统测试难

传统软件的测试有一个根基：**期望是确定的**——函数输入 1+1，期望输出 2，错了就是 bug。但 LLM 应用有两个根本不同：

**第一，输出不唯一。** 同一个问题，模型可以有一百种"正确"的说法。你不能用"等于某字符串"来断言对错——只能判断"这个回答好不好"，而"好"是模糊的、分程度的。

**第二，"好"的标准因场景而异。** 客服回答要准确+礼貌，技术问答要精确+带出处，创意写作要有风格。没有放之四海而皆准的"好"——**每个应用都要定义自己的"好"是什么。**

这就是 LLM 评测的起点：**不是找一个通用的打分器，而是先明确"对这个业务来说，什么算好的回答"。**

## 评测的四要素

任何 LLM 评测，本质上都要回答四个问题：

| 要素 | 问题 | 例子 |
|---|---|---|
| 评测集 | 拿什么题来测 | 100 条业务问题，覆盖各场景 |
| 指标 | 怎么判断答得好不好 | 命中率、相关性、拒答正确率 |
| 评判方式 | 谁来打分 | 人工 / 规则 / LLM-as-Judge |
| 基线 | 跟什么比 | 上一版本 / 竞品 / 期望标准 |

缺了任何一块，评测都不成立：

- 没有**评测集**：无题可测，只能靠感觉；
- 没有**指标**：不知道看什么，无法比较；
- 没有**评判方式**：无法规模化打分，测几条就累了；
- 没有**基线**：不知道"变好还是变坏"——**评测的核心价值是比较，孤立的分数没有意义。**

## 三类指标：各管一段

LLM 应用的指标大致分三类，分别回答不同问题：

**1. 质量指标——回答本身好不好。**
- 正确性 / 相关性：答的内容对不对、贴不贴题；
- 完整性：该覆盖的点有没有覆盖；
- 忠实性（faithfulness）：有没有编造资料外的东西（RAG 的核心指标）；
- 风格 / 语气（按业务定义）。

**2. 行为指标——该做/不该做的边界。**
- 拒答正确率：不该答的（无资料、越权）有没有正确拒绝；
- 意图路由准确率：分类分对没有；
- 引用准确率：给出的出处是否真实有效。

**3. 工程指标——成本和体验。**
- 延迟、token 消耗、成本；
- 缓存命中率；
- 错误率（调用失败、超时）。

**工程上最容易犯的错是只盯质量指标**——回答挺准，但成本翻了十倍、延迟用户受不了，一样是失败。评测要"质量 + 行为 + 工程"一起看。

## 评判方式的选择：从人工到自动化

判分方式按自动化程度递进：

```text
人工评分         最准，但慢、贵、主观、不可规模化
规则评分         快、客观，但只能覆盖可规则化的部分（格式、关键词）
LLM-as-Judge    快、可规模化、能做"主观质量"判断，但有自身偏差
```

实践中的组合是分层级的：

- **能规则化的用规则**：格式对不对、有没有出处、拒没拒答——这些不用模型判；
- **主观质量的用 LLM-as-Judge**：相关性、忠实性——用强模型按标准打分；
- **抽样的用人工**：规则和 LLM 都不确定的争议案例，人工仲裁。

## 评测集与回归：评测的真正价值

评测最容易被忽视的价值是**回归**。单次评测只能告诉你"当前水平"，而 AI 应用需要的是一套固定的评测集 + 历史基线，来回答"这次改动是变好还是变坏"：

```text
v1（当前线上）：评测集得分 92%
改切分参数 → 跑同一套题 → 得分 88%  ← 回退了，不许上线
换 embedding → 跑同一套题 → 得分 95%  ← 进步了，可以灰度
```

**固定评测集 + 可比较基线 = 回归测试**，这是 AI 应用持续迭代的安全网。没有它，每次改动都是一次"赌"。

## 评测的三个常见误区

**误区一：评测集越全越好。** 追求"覆盖所有可能的问题"会让评测集膨胀到无法维护。好的评测集是**代表性样本**：覆盖各业务场景的典型题 + 边界题 + 历史坏案例，几十到几百条足够驱动迭代，重点是精选而非量大。

**误区二：评测一次做完就完事。** 评测集要持续生长——线上每发现一个新坏案例就补进去（RAG 篇详述过的机制）。评测集是活的资产，不是一次性报告。

**误区三：追求"完美分数"。** 评测分数是相对基线用的，不是绝对真理。100 分不代表系统完美（可能你的题太简单），95 分也不代表不能用。**看趋势和回归，比看绝对值重要。**

## 小结

LLM 评测是把主观的"好不好"变成可比较数字的工程手段。四要素缺一不可：评测集（测什么）、指标（看什么）、评判方式（谁打分）、基线（跟谁比）。指标分质量、行为、工程三类一起看。核心价值是回归——固定评测集 + 基线，让每次改动有据可依。**没有评测的 AI 应用优化是玄学，有了评测，优化才是工程。**
