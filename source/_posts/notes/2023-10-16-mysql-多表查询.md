## 1. 什么是多表查询

多表查询就是一次性从好几张有关系的表里把我们需要的数据“拼”在一起查出来

直白:  将多个表的数据拼在一起, 形成一张表, 然后根据需求把需要结果查询出来的过程 (结果数据是来源于多个表的)

**为什么需要多表查询？**

想象一个电商网站的数据库，它不可能把所有信息都塞在一张巨大的表里，那样会非常混乱且冗余。所以，它会分成好几张表：

- **用户表（`users`）**：存放用户ID、姓名、电话等信息。
- **订单表（`orders`）**：存放订单ID、订单金额、下单时间，以及是**哪个用户**下的单（这里会记录用户的ID）。
- **商品表（`products`）**：存放商品ID、商品名称、价格等信息。

现在，老板问你：“查一下‘张三’的所有订单信息，要显示他的订单号和商品名称。”

你会发现，这个问题的答案分散在三张表里：

1. **用户表**：找到“张三”，得到他的用户ID（比如是 101）。
2. **订单表**：找到所有 `user_id = 101` 的订单，得到订单ID。
3. **商品表**：根据订单ID（可能要通过另一张“订单明细表”关联）找到对应的商品名称。

**多表查询**，就是写一条SQL语句，让数据库自动帮你完成这个“查找-拼接”的过程，一次性返回最终结果。

**核心思想：通过一个共同的“桥梁”字段（通常是主键和外键）把多张表连接起来。**

```sql
SELECT 列名1， 列名2...
FROM 表A
JOIN 表B ON 表A.共同字段 = 表B.共同字段; -- ON 后面就是告诉数据库，怎么把两张表“拼”在一起的规则
```

## 2. 外键与外键约束

### 2.1 什么是外键

​		概念：假设有两张表A和B，B表的某列的值引用了A表的主键列的值，则B表的这一列称为B表的外键列 (Foreign Key)，其中A表称为主表，B表称为从表。

​		如何区分主表和从表:

​		从表: 有外键字段, 通过这个外键字段 指向另一个的主键

​		主表:  有外键字段指向到自己的主键

### 2.2 外键约束

​		当两张表存在外键关系的时候，可以在从表的外键字段上添加外键约束。

外键约束的作用：

* 保证插入数据的准确性：从表中外键的值在主表主键中必须有对应的值

* 保证删除数据的完整性：主表的主键值被从表外键引用之后，主表中对应的记录不能被删除

弊端：

* 过分强调或者说使用主键／外键会平添开发难度
* 添加外键，也会降低数据增删改的性能

> 注意：**实际开发，很少使用外键约束，而是从代码层面保持表之间的关系！**

如何设置外键约束：

```properties
语法:
	[constraint 约束名] foreign key (外键字段) reference 主表名(主键)
	
放置位置:
	建表的时候, 在整个字段的最后面
```

需求:  构建一个day05_mutiple_tab库, 并在此库下创建两张表, 一个分类表、一个商品表, 并完成构建外键

```properties
/*
    关键词: foreign key

    作用:
        1- 确保从表数据的准确性: 从表中不能出现主表中不存在的数据
        2- 确保主表数据的完整性: 主表中不能删除已经被从表引用数据

    语法:  建议书写外键名字
        [constraint 外键名] foreign key (外键字段) reference 主表名(主键字段)

 */
-- 需求:  构建一个day05_mutiple_tab库, 并在此库下创建两张表, 一个分类表、一个商品表, 并完成构建外键
drop database if exists day05_mutiple_tab;
create database day05_mutiple_tab;
use day05_mutiple_tab;

-- 创建 分类表 (主表)
drop table if exists day05_mutiple_tab.category;
create table day05_mutiple_tab.category(
    id varchar(10) primary key ,
    name varchar(20)
) comment '分类表';

-- 创建 商品表 (从表)
drop table if exists  day05_mutiple_tab.product;
create table day05_mutiple_tab.product(
  pid int primary key ,
  name varchar(20),
  price decimal(10,2),
  category_id varchar(10),
  -- 外键约束
  constraint category_id_fk foreign key (category_id) references day05_mutiple_tab.category(id)
)comment '商品表';
```

外键约束的其他操作

```sql
-- 演示效果:
-- 添加主表数据
insert into day05_mutiple_tab.category values
                                              ('c01','手机'),
                                              ('c02','电脑'),
                                              ('c03','平板');

-- 添加从表数据
insert into day05_mutiple_tab.product values
                                             (1,'华为X7',2999,'c01'),
                                             (2,'联想Y9000P',18999,'c02'),
                                             (3,'三星W25',17999,'c01'),
                                             (4,'IPAD PRO 2025',7999,'c03');

-- 尝试 在 从表中添加主表中不存在的数据
-- 直接报错: Cannot add or update a child row: a foreign key constraint fails (`day05_mutiple_tab`.`product`, CONSTRAINT `category_id_fk` FOREIGN KEY (`category_id`) REFERENCES `category` (`id`))
insert into day05_mutiple_tab.product values (5,'美的冰箱2025',5999,'c04');
-- 如果非要插入怎么办?
-- 方式一: 请先在主表中增加 c04的分类
insert into day05_mutiple_tab.category values ('c04','家电');
insert into day05_mutiple_tab.product values (5,'美的冰箱2025',5999,'c04');
-- 方式二: 将从表的c04 更改为null(不引用)
insert into day05_mutiple_tab.product values (5,'美的冰箱2025',5999,NULL);
-- 尝试 在主表中删除目前被从表引用数据
-- 直接报错: Cannot delete or update a parent row: a foreign key constraint fails (`day05_mutiple_tab`.`product`, CONSTRAINT `category_id_fk` FOREIGN KEY (`category_id`) REFERENCES `category` (`id`))
delete from day05_mutiple_tab.category where id = 'c02';
-- 如果非要删除呢?
-- 需要先在从表中将引用去除:
-- 将从表对应数据删除
-- 将从表对应的数据分类的值更改为其他的值 或者 置为NULL
update day05_mutiple_tab.product set category_id = NULL where category_id = 'c02';
-- 删除主表的c02
delete from day05_mutiple_tab.category where id = 'c02';
-- 删除外键约束
alter table day05_mutiple_tab.product drop foreign key category_id_fk;
```

## 3. 表与表之间的关系

假设有 A 和 B 两张表，表之间的关系可以分为如下 3 种：

一对多关系（One To Many）

* A表一行 → B表多行

* B表一行 → A表一行

多对多关系（Many To Many）

* A表一行 → B表多行

* B表一行 → A表多行

一对一关系（One To One）

* A表一行 → B表一行

* B表一行 → A表一行

### 3.1 一对多关系

分类表中的一条数据, 对应到商品表中有多条数据

### 3.2 多对多关系

多对多举例：学生表和课程表（选课关系）

注意：多对多关系中一定有一个中间关系表，记录两张表之间的数据联系

### 3.3 一对一关系

一对一举例：员工基础信息表和员工详细信息表

实操: 尝试完成 一对一  一对多 和 多对多的建表

```sql
-- 多表关系:
-- 一对多 : 主表中一条数据 在从表中有多条与之对应  从表一条数据在主表只能1条
-- 创建 分类表 (主表)
drop table if exists day05_mutiple_tab.category;
create table day05_mutiple_tab.category(
    id varchar(10) primary key ,
    name varchar(20)
) comment '分类表';

-- 创建 商品表 (从表)
drop table if exists  day05_mutiple_tab.product;
create table day05_mutiple_tab.product(
  pid int primary key ,
  name varchar(20),
  price decimal(10,2),
  category_id varchar(10),
  -- 外键约束
  constraint category_id_fk foreign key (category_id) references day05_mutiple_tab.category(id)
)comment '商品表';


-- 多对多:  A表一条数据 可以匹配 B表中多条数据 同样 B表中一条数据也可以匹配A表中多条数据
-- 学生表
drop table if exists day05_mutiple_tab.student;
create table day05_mutiple_tab.student(
    id varchar(10) primary key ,
    name varchar(20)
) comment '学生表';
-- 课程表
drop table if exists day05_mutiple_tab.course;
create table day05_mutiple_tab.course(
    id varchar(10) primary key ,
    name varchar(20)
) comment '课程表';

-- 选课表(中间表) : 创建二个外键字段 分别和学生表主键 以及 课程表主键关联
drop table if exists day05_mutiple_tab.sc;
create table day05_mutiple_tab.sc(
    id int primary key auto_increment,
    sid varchar(10),
    cid varchar(10),
    constraint sid_fk foreign key (sid) references day05_mutiple_tab.student(id),
    constraint cid_fk foreign key (cid) references day05_mutiple_tab.course(id)
) comment '选课表(中间表)';

-- 中间表 需要通过二个外键字段 分别指向不同表的主键字段
-- 员工基本信息表
drop table if exists day05_mutiple_tab.emp;
create table day05_mutiple_tab.emp(
  id int primary key ,
  name varchar(20),
  age int ,
  gender varchar(10)
) comment '员工基本信息表';
-- 员工详细信息表: 假设它是从表
drop table if exists day05_mutiple_tab.emp_info;
create table day05_mutiple_tab.emp_info(
  id int primary key ,
  addr varchar(100),
  native varchar(20),
  constraint id_fk foreign key (id) references emp(id)
) comment '员工基本信息表';
```
