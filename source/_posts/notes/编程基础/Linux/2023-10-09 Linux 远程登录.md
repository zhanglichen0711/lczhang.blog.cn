# Linux 远程登录

先说结论：远程登录就是 SSH——服务器只开 SSH，客户端配好密钥免密登录，密码登录能关就关。

## SSH 是什么

Secure Shell：加密的远程终端协议，默认端口 22。服务端跑 `sshd`，客户端用 `ssh` 命令连接。

## 基本连接

```bash
ssh 用户名@主机IP              # 默认 22 端口
ssh -p 2222 用户名@主机IP      # 指定端口
ssh ops@1.2.3.4               # 第一次连接会问是否信任指纹，输 yes
exit                          # 或 Ctrl+D 退出
```

## 密钥登录（重点）

密码登录又慢又不安全，标准做法是密钥对：私钥留本地，公钥放服务器。

```bash
# 1. 本地生成密钥对（一路回车即可）
ssh-keygen -t ed25519

# 2. 把公钥推到服务器（输最后一次密码）
ssh-copy-id ops@1.2.3.4

# 3. 之后直接登，不再要密码
ssh ops@1.2.3.4
```

- 私钥在 `~/.ssh/id_ed25519`，**绝不能外传**；公钥 `id_ed25519.pub` 才是放服务器的。
- 权限要求：服务器上 `~/.ssh` 是 700，`authorized_keys` 是 600，权限错了密钥登录会失效。

## 用 config 管理多台服务器

编辑本地 `~/.ssh/config`：

```
Host myserver
    HostName 1.2.3.4
    User ops
    Port 22
    IdentityFile ~/.ssh/id_ed25519
```

以后一句 `ssh myserver` 就连上了。

## 传文件：scp / sftp

```bash
scp 本地文件 ops@1.2.3.4:/tmp/       # 上传
scp ops@1.2.3.4:/var/log/a.log ./    # 下载
scp -r mydir ops@1.2.3.4:/tmp/       # 递归传目录
```

## 连不上的排查顺序

1. `ping` 通不通（不通查网络/安全组 ICMP）。
2. 端口通不通：`ssh -v` 看卡在哪，或 `telnet IP 22`。
3. 云服务器查**安全组**是否放行 22。
4. 服务器上 `systemctl status sshd`，看日志 `journalctl -u sshd`。
5. 密钥登录被拒：九成是服务器上权限不对，或 `authorized_keys` 没写对。
