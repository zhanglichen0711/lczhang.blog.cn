# Linux 系统启动过程

先说结论：现代发行版的启动链就是五步——固件 → 引导器 → 内核 → systemd → 登录。看懂这条链，开不了机才知道卡在哪一环。

## 完整启动流程

```
1. BIOS / UEFI        上电自检，找到启动设备
2. GRUB2 引导器       读取引导配置，显示菜单，加载内核
3. Linux 内核         解压自身、加载 initramfs、挂载根文件系统
4. systemd (PID 1)    启动第一个进程，按 target 拉起所有服务
5. 登录界面           getty / 显示管理器，等待用户登录
```

- **initramfs** 是一个内存里的迷你系统，负责在真正根分区挂载前加载硬盘驱动。驱动不对就卡在这里。
- **systemd 取代了旧的 init**，现在是几乎所有主流发行版的 1 号进程。

## 运行级别：旧 runlevel 与新 target 对照

| runlevel | systemd target | 含义 |
|----------|---------------|------|
| 0 | poweroff.target | 关机 |
| 1 | rescue.target | 单用户（救援）模式 |
| 3 | multi-user.target | 多用户命令行，服务器默认 |
| 5 | graphical.target | 图形界面，桌面默认 |
| 6 | reboot.target | 重启 |

```bash
systemctl get-default            # 查看当前默认启动目标
sudo systemctl set-default multi-user.target   # 改为开机进命令行
sudo systemctl isolate graphical.target        # 临时切换，不重启
```

## 排查启动问题的思路

1. **卡在 GRUB 之前**：固件/磁盘问题，进 BIOS 看硬盘是否被识别。
2. **卡在 GRUB 之后黑屏**：内核或驱动问题，启动时按 `e` 编辑内核参数加 `nomodeset` 试探。
3. **服务起不来**：进 rescue.target，`journalctl -xb` 看本次启动日志，`systemctl status 服务名` 定位。

## 实用记忆点

- 查看本次启动日志：`journalctl -b`
- 查看开机耗时：`systemd-analyze`；哪个服务拖慢了：`systemd-analyze blame`
