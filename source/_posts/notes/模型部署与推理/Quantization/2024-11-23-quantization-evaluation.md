量化不是"装上就完事"——你换了模型的权重精度，必须回答：**质量掉了多少、速度与显存换回了多少、这笔交易值不值**。这一篇给出量化评估的完整方法：精度怎么测、性能怎么测、账怎么算。这是量化工程里最容易被跳过、却最重要的环节。

## 精度评估：同题对比

核心方法：**同一套评测集，FP16 与量化版各跑一遍，对比输出质量**。

```python
# 通用评测集（学术）：MMLU/GSM8K/C-Eval 等现成基准
# 但业务场景必须自建领域评测集
eval_questions = [
    "GB50204 中梁板拆模强度要求是什么？",
    "把这段描述归类为质量缺陷类别：...",
    # ... 50~100 条覆盖核心与边界的题目
]

def evaluate(model_endpoint, questions):
    """逐题请求，返回结构化结果供对比"""
    results = []
    for q in questions:
        answer = ask(model_endpoint, q)
        results.append(answer)
    return results

# 对比三份：
# fp16 = evaluate("http://fp16-server:8000", eval_questions)
# int4 = evaluate("http://int4-server:8000", eval_questions)
# 人工/规则打分：int4 相对 fp16，答案是否一致、是否仍正确
```

评估的三个层次（按成本从低到高）：

1. **结构化任务自动比**：分类、抽取、JSON 输出——直接比字段正确率，最容易量化；
2. **通用基准**：C-Eval 等学术集抽样——看通用能力退化幅度；
3. **人工抽检生成质量**：50 条代表性问答请业务专家打分——生成类任务最终裁判。

**别用单条 prompt 判断**——一次回答像不像不能代表整体质量。

## 关注两类退化信号

量化评估不能只看"平均分"，重点盯：

1. **边界/长尾题目**：量化误差在"容易的题目"上不明显，但难题目、精确引用、数学推理容易暴露退化——评测集要含这类题；
2. **输出格式稳定性**：量化模型偶尔会在格式上"飘"（JSON 不合法、漏字段）——把格式合规率单独统计。

```python
def format_rate(answers):
    import json
    ok = sum(1 for a in answers if try_parse_json(a))
    return ok / len(answers)
```

**经验法则**：INT8 通常退化 <1%、INT4 多数任务 1~5%。如果 INT4 在你的领域评测里退化明显（>5%），考虑换方案（更细 group、或对敏感层不量化）。

量化有没有赚到，用上一篇的压测方法对比三组数：

```python
# 用推理压测脚本（见"推理性能度量"篇）对比 FP16 vs INT4：
#   显存占用（nvidia-smi）
#   吞吐（tokens/s，固定 max_tokens 的并发压测）
#   p95 延迟
# 输出对比表：
#   模型版本 | 显存 | 吞吐 | p95 | 评测得分
#   FP16    | 14GB | 500  | 1.2s | 92
#   INT4    | 4GB  | 750  | 0.8s | 90
```

## 算清这笔账

拿到两边的数后，做决定靠一个简单框架：

```text
收益 = 省下的显存（能否装下目标模型/更长上下文）
     + 速度提升（吞吐/延迟改善是否可感知）
成本 = 评测得分下降幅度（在你的业务场景）

结论：
  显存不够用 → 量化是刚需（只能接受精度成本）
  显存够用但想更快 → 先试 INT8（成本最小）
  精度不可接受 → 换更细粒度 / 只量化部分层 / 用更大原模型
```

**诚实的提醒**：如果你的服务显存充足、延迟达标，**量化未必是必要的**——别为了"用上量化"而量化。优化是为业务目标服务，不是炫技。

## 量化评估的完整流程（收口）

```text
1. 建领域评测集（50~100 题，含边界与格式题）
2. FP16 基线跑一遍，记录质量分与性能数据
3. 量化（INT8 → INT4 逐级试）
4. 量化版跑同一评测集 → 对比质量
5. 压测对比性能 → 算收益/成本账
6. 达标上线；不达标则调整（group/方案/校准数据）重来
```

## 小结

量化评估 = **同一评测集对比精度 + 压测对比性能 + 算清收益成本账**。记住三个警惕：别用单条 prompt 判断、别只看平均分要盯边界题、INT4 退化明显时先试更稳方案。量化是把双刃剑——会用剑之前，先学会测剑。
