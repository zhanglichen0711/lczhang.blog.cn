微调最忌讳的一句话是"感觉变好了"——没有系统评测的微调，可能只是你记住了几条好样本。这一篇是 Fine-tuning 的收口：**怎么科学地证明一次微调有效、可以上线**。评测方法论到位，微调才不是玄学。

## 评测集：微调工程的"考试卷"

没有考试就没有学习。评测集的设计原则：

```python
eval_set = {
    "core_cases": [...],    # 核心场景：50~100 条必考
    "edge_cases": [...],    # 边界场景：该拒绝的、模糊的、长尾的
    "format_cases": [...],  # 格式场景：JSON/模板输出是否规范
    "regression": [...]     # 回归：之前修复过的坑（防止复发）
}
```

**关键纪律：评测集绝不能出现在训练集里**（否则等于开卷考试）。训练时把数据按 8:1:1 分好，评测集锁死不动——每次微调迭代都跑同一份考卷，分数才可对比。

## 微调评测的"三个维度"

大模型微调效果不能只看一个指标，至少分三层看：

### 维度一：客观指标（能算的）

| 任务 | 指标 |
| --- | --- |
| 分类/抽取 | 准确率、F1（逐类看） |
| 格式合规 | 输出能否被 JSON 解析、字段是否齐全 |
| 检索类 | Recall@K |
| 通用退化 | 跑通用 benchmark（如 C-Eval 抽样）对比微调前后 |

```python
import json

def format_ok(text: str) -> bool:
    try:
        json.loads(text)
        return True
    except Exception:
        return False

format_rate = sum(format_ok(r) for r in responses) / len(responses)
print(f"格式合规率: {format_rate:.2%}")   # 微调最直接的收益点之一
```

### 维度二：人工评测（该人看的）

生成类回答的"好不好"机器难判，抽 50~100 条让**业务专家**打分（正确性、口径、风格、出处真实性）。人工评测虽贵，但它是"领域模型好不好"的最终裁判。

### 维度三：回归与遗忘检查

微调最常见的事故是**按下葫芦浮起瓢**：领域能力涨了，通用能力崩了。必须做对比：

```text
同一份评测集：
  基础模型（未微调）得分
  vs 微调后模型得分
要求：领域维度 ↑，通用维度不 ↓（或下降可接受范围内）
```

跑一下"微调前后通用能力对比"，灾难性遗忘立刻现形。

## 和什么对比：单模型分数没有意义

一次微调"涨了多少分"，参照系必须有：

| 对比对象 | 回答的问题 |
| --- | --- |
| 基础模型（零微调 + 提示词） | 微调是不是真的有必要 |
| 上一次微调版本 | 这次迭代有没有进步 |
| RAG 增强的提示词方案 | 微调 vs 检索增强谁更值 |

**最高频的错误**：只报告"微调后 92 分"，却没和"加两行提示词的基础模型 88 分"对比——那 4 分可能不值得一次微调的成本。

## 上线：A/B 与灰度

评测集过关不等于线上无忧。上线走稳妥流程：

1. **影子模式**：新旧模型同时跑线上请求，只记日志不切换——离线对比"如果上线会怎样"；
2. **A/B 分流**：小流量（5%）切新模型，对比用户反馈/人工抽检；
3. **回滚预案**：保留旧模型权重与配置，随时一键回滚；
4. **监控**：上线后盯输出格式失败率、空回答率、平均长度异常。

```text
灰度节奏：影子对比 → 5% → 30% → 全量（每步都有回滚保险）
```

## 一次微调迭代的标准流程（收口）

把 Fine-tuning 六篇串成一个可复用的迭代闭环：

```text
1. 明确目标：这次微调要解决什么（格式？口径？拒绝行为？）
2. 构造数据：精品示范 + 边界样本 + 专家复核（数据篇）
3. 选择策略：数据量决定冻结范围 / 直接用 LoRA（策略、LoRA 篇）
4. 训练：少 epoch + 小学习率（SFT 篇）
5. 评测：固定评测集 + 三维度 + 与基线对比（本篇）
6. 未达标 → 回到 2（修数据）
7. 达标 → 影子模式 → A/B → 灰度上线
```

**微调是"数据迭代"工程，不是"训练一次"工程**——大多数效果提升来自第 2 步和第 5 步的反复打磨。

## 小结

微调评测 = **固定评测集（不泄漏、含边界）+ 三维度评估（客观指标/人工打分/回归遗忘）+ 与基线对比**，上线走影子模式与灰度回滚。这一整套"评测-对比-灰度"的工程纪律，决定了一次微调是"可复现的能力提升"还是"自我感觉良好"。它会成为你做任何模型改进工作的基本方法论——无论改的是 BERT 分类、LoRA 微调，还是换一个更强的基座。
